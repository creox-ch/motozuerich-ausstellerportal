# Тесты, которым нужна настоящая база

В общий прогон (`npm test`) они **не входят** — исключены в `playwright.config.js`.

## Почему они здесь, а не в `tests/e2e`

Публичная страница плана залов читает каталог площадок **на сервере**, при
отрисовке. Такой запрос нельзя перехватить через `page.route`: это не сетевой
вызов страницы, а обращение сервера к базе, браузер о нём не знает.

Оставить их в общем прогоне означало бы либо гонять тесты против боевой базы,
либо городить в рабочем коде ветку «если тесты, то фикстуры». Первое опасно,
второе делает код хуже ради тестов.

## Что они проверяют

`hallenplan.live.spec.js` — витрину: план открывается без входа, площадки
выбираются, вместо неизвестной цены стоит `XX`, форма заявки требует согласия.

Отдельный блок — **мобильный экран**, и он здесь не для галочки: у выставки
71% трафика с телефонов. Первая версия страницы на 375 пикселях была
нерабочей — колонка с планом схлопывалась в ноль, а площадки в плане
получались размером 5×4 пикселя. Тест это фиксирует, чтобы не вернулось.

## Как запустить

Нужны настоящие переменные окружения (`.env.local`) и запущенное приложение.

```bash
npx playwright test tests/live --config=playwright.live.config.js
```

## Что это значит для CI

Витрина в автоматическом прогоне не покрыта. Прогонять эти тесты руками —
после изменений в плане залов, в форме заявки и в раскладке страниц.

Если однажды заведём отдельную тестовую базу, слой можно будет вернуть
в общий прогон: тогда же имеет смысл перенести туда pgTAP-проверки.
