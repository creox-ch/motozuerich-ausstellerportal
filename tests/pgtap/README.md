# pgTAP: тесты модели доступа

Здесь один файл — [`rls_access.sql`](rls_access.sql). Он проверяет инвариант,
на котором держится вся приватность портала: **RLS включён на всех таблицах
`mz_*`, политик нет ни одной**, поэтому из браузера в базу не попасть, а весь
доступ идёт через наши API-роуты ключом `service_role`.

## Почему это отдельный слой, а не обычный тест

Playwright-тесты проверяют код приложения. Но дыру можно открыть, вообще не
трогая код: достаточно в дашборде Supabase нажать «New policy» и разрешить
чтение роли `anon` — «чтобы быстро посмотреть данные из фронта». После этого
приложение работает как прежде, тесты зелёные, а данные компаний открыты всем,
у кого есть публичный ключ. Такую правку ловит только проверка самой базы.

## Как запустить

Строка подключения — в Supabase: Project Settings → Database → Connection string
(роль владельца, не anon).

```bash
psql "$DATABASE_URL" -f tests/pgtap/rls_access.sql
```

Или через `pg_prove`, если он установлен:

```bash
pg_prove -d "$DATABASE_URL" tests/pgtap/rls_access.sql
```

Или просто вставить содержимое файла в **SQL Editor** в дашборде Supabase
и нажать Run — TAP-строки видно построчно. Это самый простой способ, и он
не требует ничего устанавливать.

Всё внутри `begin … rollback`, боевые данные не меняются.

## Почему не в CI

Тесту нужна живая база и строка подключения с правами владельца. Класть такой
секрет в GitHub Actions ради одного файла — размен не в нашу пользу: секрет
живёт постоянно, а проверка нужна редко.

Правило вместо автоматизации: **прогонять после каждого изменения схемы и после
любой ручной правки прав в дашборде.** Это тридцать секунд.

Если позже захочется в CI — понадобится отдельная тестовая база и её секрет
в репозитории, и тогда же имеет смысл гонять на ней остальные тесты, которые
сейчас обходятся моками.

## Что тест НЕ проверяет

Что роуты приложения правильно ограничивают доступ по компании. Это другой
слой: за него отвечают integration-тесты, где экспонент A пробует достать
данные экспонента B. pgTAP отвечает только за то, что мимо роутов в базу
не зайти вовсе.
