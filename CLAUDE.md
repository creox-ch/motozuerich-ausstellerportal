## Команды

Node на машине есть (v24). Проверять **до** пуша, а не только на CI.

```
npm run dev     # http://localhost:3000
npm test        # 335 тестов: unit + integration + e2e, внешние сервисы не нужны
npm run build   # ловит ошибки сборки за секунды
npx playwright test --config=playwright.live.config.js   # живой слой, нужна настоящая база
```

⚠️ `npm test` сначала делает **продакшен-сборку** и поднимает `next start` —
отсюда лишняя минута. Так сделано намеренно: против `next dev` тесты флейчили,
потому что он собирает маршрут при первом обращении, а параллельные запросы
попадали в середину сборки. Подробности — в комментарии `playwright.config.js`.
Не переводить обратно на `next dev` ради скорости.

Git — из PowerShell, не из песочницы.

## Незыблемое

**RLS deny-all.** На всех таблицах `mz_*` RLS включён, политик **ноль**. Браузер
в базу не ходит вообще — читает и пишет только сервер ключом `service_role`.
Появившаяся policy = дыра; инвариант закреплён `tests/pgtap/rls_access.sql`.

**Права — только через `lib/auth.js`.** `requireCompany` для кабинета,
`requireStaff` для админки. Идентификатор компании берётся **из сессии, никогда
из тела запроса** — иначе подстановка чужого id переписывает чужие данные.

**Гард в каждой странице, а не только в layout.** В Next 14 они рендерятся
параллельно: решение layout перенаправить не мешает странице выполниться.

**Ленивая инициализация клиентов** (`lib/supabase.js`, `lib/email.js`). Без неё
сборка на Vercel падает: при build переменных окружения нет.

**`runtime = 'nodejs'`** в каждом роуте.

**Два комплекта размеров у площадки, и смешивать их нельзя.**
`breite_m`/`tiefe_m`/`flaeche_m2` — договорные, из прайса, идут в счёт.
`plan_b`/`plan_t`/`pos_x`/`pos_y` — как площадка нарисована на публичном плане
motozuerich.ch. Это схема, а не чертёж: ярус Galerie нарисован полосой глубиной
2.78 м при проданных 7–84 м². Рисуем по `plan_*` (`lib/plan-geometrie.js`),
считаем и продаём по договорным. Слить их в одну пару колонок = дать триггеру
`mz_stands_flaeche` переписать проданные метры картинкой.

**Порядок проверок в роуте:** конфигурация → права → разбор тела → валидация →
база. Права раньше разбора тела: иначе по кодам ответа можно нащупать формат
данных, не имея доступа.

**Письмо не валит операцию**, ради которой отправлялось, — кроме случаев, где
письмо и есть операция (код входа, приглашение).

## Соглашения продукта

**`XX` вместо неизвестных данных.** Сроки и часть цен бизнесом не заданы.
Показывать `XX` красным, как в прототипе, а не подставлять правдоподобные числа:
цена читается как предложение, а выдуманное число переживает запуск незамеченным.

**Цены живут данными, не разметкой** (`mz_preise`, `mz_service_katalog`).
Появление настоящих сумм = заполнение таблицы, не задача на разработку.
Все 109 площадок трёх залов заполнены из прайса — цена задаётся **на каждую
площадку отдельно**, формулы за метр нет. Пусто пока в `mz_service_katalog`:
цены на технику, рекламу и парковку бизнесом не названы.

**Витрина — это продажа B2B, а не форма обратной связи.** Отсюда правила,
которые нельзя «упростить»:

- цена **не попадает в разметку**, пока не оставлен контакт. Не прячется
  стилями — отсутствует. Закреплено тестом по телу ответа;
- в гейте спрашиваем компанию, а не только почту: `info@` не квалифицирует лид;
- **два согласия, а не одно.** Обработка обязательна, новости добровольны.
  Швейцарский UWG Art. 3 Abs. 1 lit. o: «покажите цену» не даёт права слать
  маркетинг. Согласие на новости повторным визитом только включается —
  отказ оформляется отпиской;
- заявитель получает подтверждение немедленно: тишина после формы читается
  как «они не работают»;
- заявку можно оставить **без выбора площадки** — залы размечены не все,
  а покупатель приходит тогда, когда приходит.

**Каталог показывает только настоящие площадки.** Выдуманных в базе нет:
человек, выбравший несуществующее место, создаёт работу Messeleitung и портит
первое впечатление. Площадка без геометрии остаётся в списке, но не на плане,
и под планом стоит счёт таких площадок — молча их не показать значит соврать
про размер зала. Зал вообще без разметки показывается списком.

**Портал закрыт от поисковиков целиком** — решение Иванны. `noindex` на всех
страницах, `robots.txt` запрещает обход, карты сайта нет. Прототип закрыт
заголовком `X-Robots-Tag` (метатег в статический файл не вставить).
Open Graph оставлен: он про превью ссылки в письме, не про поиск.

**Немецкий в интерфейсе, русский в комментариях и документации.**

## Тесты

Четыре слоя под одним раннером Playwright:

- `tests/unit` — чистые функции из `lib/`
- `tests/integration` — настоящие роуты, ветки до обращения к базе
- `tests/e2e` — страницы через продакшен-сборку, наши API замоканы
- `tests/live` — **нужна настоящая база**, в общий прогон не входит (см. его README)
- `tests/pgtap` — инварианты RLS, запускать после каждой правки схемы

Фичу делать **сразу с тестами**. И проверять, что тест может покраснеть по той
причине, ради которой написан, — за один день было четыре зелёных проверки,
которые ничего не проверяли.

## Грабли этого проекта

- **Vercel отдавал `public/` как статику**, игнорируя сборку Next: у проекта
  оставался Framework Preset «Other». Лечится `"framework": "nextjs"` в `vercel.json`.
- **Код входа восьмизначный**, а не шестизначный. Длину не зашивать —
  это настройка Supabase.
- **Мобильный.** У выставки 71% трафика с телефонов. `minmax(0,1fr)` рядом
  с колонкой 320px на 375px даёт первой колонке **ноль**. Цели для нажатия ≥44px.
  Кликабельные элементы внутри SVG не годятся: их не видят читалки и в них
  не попасть пальцем — рядом нужен список настоящих кнопок.
- **Письма с тестовых окружений** перехватываются `PORTAL_MAIL_OVERRIDE`.
  В Production переменной быть не должно. Какие перехваты включены сейчас —
  видно в `/api/health`, поле `aktiveUmleitungen` (имена, не адреса).
- **Тесты против `next dev` флейчат.** Он собирает маршрут при первом
  обращении; параллельные запросы попадают в середину сборки и получают 500
  с ошибкой `Cannot read properties of null (reading 'useContext')` — она
  из отрисовки страницы ошибки и к нашему коду отношения не имеет. Стоило
  получаса 13.08. Лечится не прогревом и не ретраями, а прогоном против
  продакшен-сборки; так и сделано.
- **Схема и база расходятся молча.** Таблицу заводят через MCP, в
  `supabase/schema.sql` она не попадает — ломается только создание базы с нуля,
  то есть узнаём в худший момент. Заводя таблицу или колонку, сразу дописывать
  файл и **оба** списка доступа в конце (`enable row level security`,
  `revoke truncate`).
