# Ausstellerportal · MOTO-ZÜRICH 2027

Портал для экспонентов выставки MOTO-ZÜRICH (19–21.02.2027, StageOne и Halle 550,
Zürich-Oerlikon).

**Прод:** https://motozuerich-ausstellerportal.vercel.app
**Vercel:** проект `motozuerich-ausstellerportal`, team `creox`
**Состояние и открытые вопросы:** [STATE.md](STATE.md) — читать первым
**Задачи:** [docs/backlog.md](docs/backlog.md) · **замысел:** [docs/ARCHITEKTUR-PLAN.md](docs/ARCHITEKTUR-PLAN.md)

## Состояние

⚠️ **Развёрнут, но не боевой.** Код в проде и работает, но клиентов туда
не ведём, ссылку никому не рассылали, настоящих экспонентов в базе нет.
Подробности и что осталось до запуска — в [STATE.md](STATE.md).

Построены обе половины продукта:

- **Витрина** (публичная, входа не требует): каталог 109 площадок в трёх залах
  с планом и ценами, показ цены в обмен на контакт, форма заявки, уведомление
  Messeleitung.
- **Кабинет** (по коду на почту): все 11 разделов прототипа — Übersicht
  со сроками, план залов, профиль, техника, маркетинг, логистика, активности,
  совместный маркетинг, документы и счета, переписка, пропуска.
- **Админка** для Messeleitung: заявки, компании, доступы, статусы площадок,
  документы, переписка, логистика.

`public/prototyp.html` остаётся по адресу `/prototyp` как справочный макет:
это функциональная спецификация, по которой строился портал.

Красные `XX` — не недоделка, а честная пометка: бизнес ещё не назначил
эти сроки и цены. Список — в [docs/fragen-an-messeleitung.md](docs/fragen-an-messeleitung.md).

## Разработка

Нужен Node 20+ (проверено на 24.19.0).

```bash
npm install
npm run dev     # http://localhost:3000
npm test        # 335 тестов: unit + integration + e2e
npm run build   # ловит ошибки сборки до пуша
```

Тесты не требуют ни Supabase, ни Resend: e2e мокают наши API, integration
проверяют ветки до обращения к базе, заглушки env заданы в `playwright.config.js`.

⚠️ `npm test` сначала делает продакшен-сборку и поднимает `next start` — отсюда
лишняя минута. Против `next dev` тесты флейчили; подробности в комментарии
`playwright.config.js`.

`/api/health` показывает, каких переменных окружения не хватает — только имена,
никогда значения.

## Структура

```
app/            страницы и API-роуты
  hallenplan/   публичная витрина: план залов, гейт цен, заявка
  portal/       кабинет экспонента (11 разделов)
  admin/        рабочее место Messeleitung
  api/health/   служебная проверка конфигурации
lib/            серверные модули: права, база, почта, цены, валидация
tests/          unit · integration · e2e · live · pgtap
public/         статика, включая прототип
docs/           состояние, бэклог, вопросы бизнесу, юридические черновики
supabase/       схема БД (21 таблица), сиды каталога и цен, чистка тестовых данных
```

## Деплой

Push в `main` → продакшен. Ветка → preview-деплой со своим адресом.

Переменные окружения — в Vercel (Project → Settings → Environment Variables),
список и назначение в [.env.example](.env.example). Vercel применяет их только
на следующем деплое: после правки нужен Redeploy.

## Перед реальным запуском

Полный список — в [STATE.md](STATE.md), раздел «Перед запуском». Коротко:

- **вычитка Datenschutz и Impressum юристом** — обе страницы черновики
  ([docs/rechtliches-review.md](docs/rechtliches-review.md)). До этого раздел
  Ausweise не собирает никаких данных о сотрудниках, и инвариант закреплён
  тестом;
- снять `PORTAL_MAIL_OVERRIDE` — сейчас вся почта портала уходит в тестовый
  ящик, и это правильное состояние на время проверок. Что перехвачено, видно
  в `/api/health`;
- убрать тестовые данные: `supabase/cleanup-testdaten.sql`;
- ручная проверка по [docs/testplan-manuell.md](docs/testplan-manuell.md) —
  ни один экран пока не видел живого человека.
